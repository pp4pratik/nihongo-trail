# Nihongo Trail

Read `docs/REQUIREMENTS.md` before making any structural change.
It is the source of truth for scope, data model, and phasing.

Rules:
- Build strictly phase-by-phase (see §16). Do not start Phase N+1 work
  until Phase N acceptance criteria in §16 pass.
- The data model in §12 is contractual. Changing it requires a migration
  (see §12.9) and a note in docs/DECISIONS.md.
- Never break the resume-session contract in §10.4.
- All content data is generated by scripts in `scripts/ingest/`.
  Never hand-edit files in `public/content/`.
