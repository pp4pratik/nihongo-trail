# Nihongo Trail

A single-user, offline-capable web app that takes a complete beginner from zero Japanese
to solid JLPT N5 competence through short daily sessions — Duolingo-style teaching units,
an FSRS spaced-repetition retention engine, and full ownership of your own data.

## Why

Existing options each fail in a specific way for this use case:

- **Duolingo** teaches enjoyably but its retention model is weak and it won't show you what
  you actually know versus what you've merely seen.
- **Anki** has excellent retention but zero teaching structure and a high setup burden.
- **WaniKani** is excellent for kanji but ignores grammar and doesn't teach kana.
- **Textbooks** are structurally sound but have no scheduling and no feedback loop.

Nihongo Trail combines the teaching structure of a course, the retention engine of Anki,
and the session design of Duolingo — for one learner, with full ownership of the data.

The thing this app is actually built around: **honesty over flattery.** A decay indicator
on the lesson map surfaces when what you "completed" has decayed below a real retrievability
threshold — most apps' progress bars only ever go up, which quietly overstates what you
actually remember. See [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) §1.5 and §9.7 for the
full design principles.

## Status

**Phase 1 of 5 complete** — the Kana MVP. Hiragana and katakana are fully teachable and
reviewable offline, with the full FSRS-backed retention engine and the resume-from-anywhere
guarantee working end to end. Vocabulary, kanji, and grammar (real N5 content) land in
Phase 2+.

See [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) §16 for the full phased plan and
[`docs/DECISIONS.md`](docs/DECISIONS.md) for architecture decisions made along the way.

## Running it

Requires Node ≥ 20.

```bash
npm install
npm run content:build   # generates public/content/*.json from scripts/ingest/
npm run dev
```

Open the printed localhost URL. The app works fully offline after the first load — try it:
load the page once, then kill the dev server and reload. It should keep working.

```bash
npm test         # unit + integration tests (vitest)
npm run lint      # eslint
npm run typecheck # tsc --noEmit, project-wide
npm run build     # production build with PWA/service-worker generation
```

## How it's built

React 19 + TypeScript, Vite, Tailwind CSS, Dexie (IndexedDB),
[`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs) for spaced repetition,
React Router. Fully static — no backend, no account, no server in Phase 1–4. See
[`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) §13 for the full architecture and
[`CLAUDE.md`](CLAUDE.md) for the project's working rules.

Content (kana, curriculum, and eventually vocabulary/kanji/grammar) is never hand-edited —
everything in `public/content/` is generated by scripts in `scripts/ingest/` from either
hand-authored source data (`content/authored/`) or open datasets (Phase 2+). Run
`npm run content:build` after changing anything under `scripts/ingest/` or `src/lib/kanaTable.ts`.
